# Does cvaa serve its mission when policing gridatlas? A computer science study scope

Fresh clones at 2026-08-30 16:xx UTC: Ventusltd/cvaa at daada0f, Ventusltd/gridatlas at 22ecad9.

## 1. Mission under test

cvaa claims: memory lives in files a machine checks; failure modes caused by memory or
context loss (hostile amnesia) are encoded once as vaccines and can never recur unnoticed
in any repo that calls the registry.

### 2.2 What the series shows

- 18 to 2 happened in one human commit (e587e8b) that archived 21 workflows. cvaa did not
  cause it; the diagnosis document did. cvaa was not installed in gridatlas at any point in
  this series. Every number above was produced by running cvaa locally after the fact.
- derived-state-not-authored appeared at fc7a0b5 and survived six scope commits unchanged.
  gridatlas's own lint passed on every one. The two checkers disagreed for an hour and nobody
  knew, because cvaa was not in the loop. This is the central result: a vaccine registry
  that is not called has a policing effect of exactly zero.
- The six scope commits changed nothing cvaa measures. cvaa scores process hygiene, not
  whether the atlas was in fact modularised. That is by design, and it is a limit.

### 2.3 Diseases present in gridatlas that no vaccine caught (false negatives)

FN1 Generation went backwards: 202608301528 then 202608301430. Cause: the scope loop stamps
    generations in BST, the live verifier stamps in UTC. Commit times prove it (14:25Z
    stamped 1524; 14:30Z stamped 1430). No vaccine checks monotonic generations or a single
    timezone. This is a pure hostile-amnesia disease: two sessions, two clocks.
FN2 Off-ledger commits: two human commits (e587e8b, bb8c28a) on main reference no scope file.
    The ledger is not the only path to main. No vaccine checks that every commit cites a scope.
FN3 The "agent loop" never ran an agent. tools/scope/advance.mjs applied pre-authored payloads
    (tools/scope/payloads, tools/scope/patches); six scopes landed in seven minutes with no
    model call. context-diet and agent-quarantine passed vacuously because there is no agent
    step to inspect. The scope files say "the agent does X"; reality is deterministic replay.
    Replay is arguably safer, but the ledger misdescribes what happened, which is drift.
FN4 The loop's schedule was retired in scope 6. The stated requirement was a perpetual loop.
    self-terminating-loops only inspects scheduled workflows, so a loop with no schedule is
    invisible. There is no loop-exists vaccine.
FN5 rollback-exists passed on a string match for "roll back". Rollback was never exercised.
FN6 The live-site claim (postcode fly-to works) is attested by gridatlas's own verifier and
    by nothing independent. cvaa has no network by design, so it cannot check it, and does
    not check that the attestation itself is fresh or derived.

### 2.4 True positives, and their quality

TP1 chaining-token: real. `|| github.token` silently degrades to a non-chaining token.
TP2 derived-state-not-authored: real but contract-dependent. The antibody assumed
    `state --stdout` prints the file; gridatlas prints a status line. Half a false positive:
    the disease (STATE not provably derived) is real, the mechanism was never agreed.

### 2.5 Registry-level observations

- Antibodies are regex over YAML text. Cheap and honest, but shallow: they detect the
  presence of words, not behaviour. A workflow that says "roll back" in a comment passes.
- Fixtures in selftest.mjs are synthetic minimal repos written by the same author as the
  antibodies. They prove the antibody runs, not that it matches real-world variety.
- The runner has never executed on GitHub against a consumer. cvaa's own selftest has run
  twice, green. That is the entire operational history.

## 3. Verdict

cvaa serves its mission as a registry and a runner. It has not yet served it as a policeman,
because it has never been called by the repo it was built to police. When run after the fact
it found two real diseases and missed six, four of which are textbook amnesia (two clocks,
off-ledger work, ledger that misdescribes execution, loop quietly retired). The misses are
all encodable as vaccines in the existing format, which is the strongest evidence the format
is right and the coverage is young.

## 4. Study design

RQ1 Does a machine-checked file registry reduce recurrence of amnesia-class regressions in a
    repo maintained by fresh-context sessions, compared with the same repo before?
RQ2 What is the false-negative rate of regex antibodies against a hand-labelled corpus of
    real commits, and does adding structural antibodies (parsed YAML, git metadata) reduce it?
RQ3 Does the presence of the registry change human and model behaviour (fewer off-ledger
    commits, fewer new workflows) even before it is enforced, i.e. a Hawthorne effect?

H1 Findings per commit fall and stay down once the consumer workflow is installed and
   required on pull requests.
H2 At least half of the six FNs above are caught by new vaccines that need only git metadata
   and scope-file front matter, with no semantic analysis.
H3 Off-ledger commit rate drops to zero once every-commit vaccines run on push.

Method
M1 Natural experiment on gridatlas history: baseline = commits 17d96ed..22ecad9 (this file's
   table). Treatment = every commit after the consumer workflow lands. Metric = findings per
   commit, off-ledger commits per day, backwards generations per day, mean time to detect.
M2 Labelled corpus: a human labels each commit in both repos with the diseases present.
   Compute precision and recall per vaccine. Target recall 0.9 on amnesia-class diseases.
M3 Ablation: run the registry with each vaccine removed; measure which findings vanish.
   Vaccines whose removal changes nothing over 30 days are candidates for superseded_by.
M4 Add six vaccines for FN1..FN6 as generation 2026083017xx, re-run M1 and M2.

Instruments
- inoculate.mjs --sarif per commit, stored under machine-learning/records in gridatlas.
- A replay script (this study's tools/replay.mjs) that checks out each commit and runs the
  registry, producing the table in 2.1 automatically.
- Labels kept as timestamped markdown in cvaa/studies/, one per commit range.

Threats to validity
- Single repo, single maintainer, single week. Generalisation is not claimed.
- The author of the antibodies is the author of the labels. Mitigate by having ChatGPT
  label independently and measuring inter-rater agreement.
- Replay is not enforcement; findings found later are not findings prevented.
