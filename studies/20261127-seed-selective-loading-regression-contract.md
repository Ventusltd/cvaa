# Proposed regression contract: selective loading, evidence and operational relevance

27 November 2026 | STUDY / UNVERIFIED as executable safeguards

This is a study, not a registered vaccine. CVAA requires a tested executable antibody and lock entry; this document does not alter the registry, declare immunity or claim CI success.

## Failure mechanisms to investigate

GridAtlas combines pre-snapped topology, compressed analytical partitions, render-ready GeoJSON, immutable content identity, direct worker delivery and on-demand retrieval. Preserve the observable benefits rather than assuming a particular library is always necessary. The map-ready manifest specifically records 4,106 400 kV features, 1,469,778 GeoJSON bytes, no duplicate critical fetch, no main-thread JSON parse for that critical source, and pre-snapped topology. These are release-contract claims and recorded artefact values, not a fresh benchmark.

| Proposed safeguard | Required positive and negative witnesses |
| --- | --- |
| Deterministic source closure | Pinned data/code hashes; correct output for same inputs; mutate one fixture and prove mismatch/refusal. |
| Initial usable view | Run cold and warm real-browser trials; assert critical layer actually renders, not just HTTP success. Delay or remove optional layers and prove the critical view still works or clearly reports failure. |
| No duplicate critical work | Instrument network requests, worker tasks and main-thread parse; inject duplicate fetch/parse and demonstrate detection. |
| Deferred loading and bounded memory | Assert disabled optional layers do not cause unnecessary payload processing; toggle repeatedly, measure heap/retained data and responsiveness; introduce an unbounded-retention fixture. |
| Stable identity and cache | Same content retains same identity; changed bytes must invalidate old evidence; corrupt a cached payload and require explicit failure. |
| Partial data and freshness | Missing, stale, failed and unsearched remain distinct from zero/complete. Assert coverage denominators and refusal paths on synthetic fixtures. |
| Composition and interaction | Compare dark/satellite and multiple zooms, verify layer toggles and selection against fixture identities; run desktop/mobile Chromium and WebKit. A screenshot alone is insufficient. |
| Export provenance | FILE-menu source export records selected/loaded layer scope, source versus data, revisions/hashes and unavailable sections; compare cold and expanded state. Large export is not proof of executable complexity. |
| Honest operational census | Historical/current/published/executed/essential populations remain distinct; shared IDs counted once; known-answer fixtures include historical-only, shared, untested and dynamically loaded code. |
| Replay before promotion | A declared capability must have input/output evidence, exact dependencies, bounded passing and failing cases; structural similarity/co-occurrence alone cannot promote a candidate. |

## Acceptance and implementation sequence

1. Inventory existing CVAA checks and GridAtlas browser proofs; reuse tested antibodies, avoid conflicting duplicate checks.
2. Pin the exact release and fixtures. Measure real cold/warm runs, first usable frame, request counts, payload bytes, worker versus main-thread activity, memory where supported and repeated layer changes. Separate harness and dependency failures from product failures.
3. Establish device- and dataset-specific budgets from reproducible baselines, not arbitrary universal thresholds. Record browser/device, network mode, sample count, percentile and limitations; report unsupported memory metrics as unknown.
4. Implement checks in isolated test scope. Provide diseased fixtures and prove the proposed antibody fires, then prove a healthy fixture passes.
5. Only after review, add timestamped vaccine documents, regenerate vaccines.lock and run registry/selftest per README. Consumer adoption requires pinned version and destination-repository approval.
6. Keep actual served-byte verification, provenance and evidence receipt as release gates. Do not move live pointers or weaken existing checks.

## Scope limits

The owner reports that GridAtlas's FILE-menu source print can exceed 3,000 pages with loaded layers. This is distinct from Spider Printer and is not a crash-free guarantee. No new performance test or antibody was executed in this research handover. Do not claim that all layers work simultaneously or that coverage is comprehensive. No production changes requested.
